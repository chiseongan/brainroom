# BrainRoom 보안 문서

독자: 이 저장소를 배포하거나 고치는 개발자. 무엇을 어떻게 막았는지, 무엇을 막지 못하는지, 배포 때 무엇을 해야 하는지를 적었습니다.

"완벽하다"는 뜻이 아닙니다. 아래 표의 공격은 시험으로 확인했고, 막지 못하는 것은 [남은 위험](#남은-위험)에 그대로 적었습니다.

## 누구를 막는가

| 공격자 | 할 수 있는 것 | 막는 곳 |
|---|---|---|
| 인터넷의 낯선 사람 | 저장소가 공개라 코드와 Firebase 설정을 봄. 직접 Firestore·프록시 호출 | 규칙, 프록시 로그인 확인, 한도 |
| Google 로그인한 낯선 사람 | 자기 방 만들기, 프록시 호출 | 규칙, 사용자별·전체 비용 한도 |
| 초대 링크를 받은 **악의적인 팀원** | 앱을 거치지 않고 규칙이 허락하는 무엇이든 씀 | 규칙, 데이터 정화, CSP |
| 교수자 | 자기 권한 안에서 직접 읽기 | 규칙 |
| 같은 PC의 다음 사용자 | 브라우저 저장소 접근 | 계정별 토큰 분리, 로그아웃 때 삭제, 암호화 |

브라우저 앱이라 **클라이언트 검사는 보안이 아닙니다.** 앱을 거치지 않고 Firestore를 직접 부를 수 있으므로 권한은 전부 규칙에서 판단합니다.

## 방어 층

**1. Firestore 규칙** ([firestore.rules](../firestore.rules))

- 공유 범위: 나만 기록은 본인만, 교수자는 "교수자까지" 기록만 내용을 읽음
- 팀원 칸 선점(`claims`): 한 칸에 계정 하나. 이름을 도용해 기록을 쓸 수 없음
- 명단(`roster`): 팀원은 내 칸만, 팀장은 모두. 이름을 바꿔 기여를 속일 수 없음
- 위조 차단: 작성자·시각(미래 불가)·투표(내 표만)·보정 확인자·변경 이력 작성자·접속 표시·회의 종료자
- 분류 변경은 그 기록의 보정 요청을 확인할 때만. AI 대화 원문은 고칠 수 없음
- 저장된 회의 요약은 고칠 수 없음. 교수자 공유는 시작한 사람·팀장만
- 기록 없이 횟수만 늘릴 수 없음 (`itemMeta`는 `items`와 함께만)
- 동의: 약관·개인정보 동의가 없으면 방을 만들거나 들어갈 수 없음. 만 14세 미만은 보호자 승인까지 필요하고, 혼자 나이 답을 바꾸거나 스스로 승인할 수 없음
- 형식 검사: id·색·주소·좌표·길이 (`javascript:` 주소, HTML이 든 색 거부)
- 초대: 7일 만료, 재발급, 틀린 코드 기록(계정·종류별 하루 1건이라 도배 불가). 링크를 열면 참여 전에 묻습니다
- 연동 대상은 팀장만: 팀원이 피해자의 비공개 저장소를 지정해 피해자의 토큰으로 내용을 가져오게 하지 못합니다
- 처리한 보정 요청은 다시 쓸 수 없음
- 방 삭제는 두 단계 (`deleting` 표시 후에만 남의 기록·이력 삭제)

규칙은 요청 하나에 표현식 1,000개, 묶음 하나에 문서 읽기 20개까지만 평가합니다. 명단을 배열로 검사했을 때 8명에서 이 한도에 걸려 문서로 나눴고, 방 올리기는 24건씩 묶습니다.

**2. 데이터 정화** ([js/sanitize.js](../js/sanitize.js))

Firestore 문서, 불러온 파일, 교수자 제출 파일을 화면에 넘기기 전에 거릅니다. 규칙이 막기 전에 저장된 데이터와 파일도 들어올 수 있어서입니다. 화면 코드가 id·색·좌표를 HTML에 넣으므로, **새 칸을 화면에 넣을 때는 여기에도 추가해야 합니다.**

**3. CSP** ([index.html](../index.html))

위 둘이 뚫려도 인라인 스크립트, `onerror` 같은 이벤트, `javascript:` 링크, 낯선 서버의 스크립트, 낯선 서버로의 전송, 낯선 iframe을 막습니다. GitHub Pages는 헤더를 줄 수 없어 `<meta>`로 넣었고, 그래서 다른 사이트의 iframe 삽입은 [js/guard.js](../js/guard.js)가 막습니다. 외부 스크립트는 버전을 고정하고 SRI 해시로 확인합니다.

프록시를 배포하면 `connect-src`의 `https://*.workers.dev`를 실제 주소로 좁히세요.

**4. 프록시** ([worker/src/index.js](../worker/src/index.js))

Firebase 토큰 서명·대상·만료, Google 로그인만, 선택적 메일 도메인 제한, BrainRoom 출처만, 하루 요청·하루 예산·월 예산, TURN 요청 제한(사람당 하루 30회, 자격 4시간), Figma 그림 주소만, 프롬프트의 데이터 칸 탈출 차단. 비밀 값은 응답에 나가지 않고 캐시도 하지 않습니다.

**5. 브라우저 안의 토큰** ([js/secure.js](../js/secure.js))

꺼낼 수 없는 AES-GCM 키로 암호화해 저장하고, 계정별로 따로 둡니다. 로그아웃할 때 지울지 묻습니다. 암호화는 **저장소 파일을 복사해 가는 공격**만 막습니다. 같은 사이트에서 스크립트가 실행되면 토큰을 쓸 수 있으므로, 3번까지 포함해 막습니다.

**6. Chrome 확장**

서버로 보내지 않고 BrainRoom 탭으로만 전달합니다. 메시지마다 어느 화면에서 왔는지 검사합니다. 배포용 zip([tools/build_extension_zip.py](../tools/build_extension_zip.py))에는 `localhost` 권한이 들어가지 않습니다.

## 시험

| 시험 | 확인하는 것 |
|---|---|
| `tests/rules` | 위조·권한 공격을 실제 규칙에 시도 |
| `tests/e2e`의 XSS 시나리오 | 모든 칸에 공격 문자열을 넣고 모든 화면(교수자·제출 파일 포함)을 열어 주입·실행이 없는지 |
| `tests/e2e`의 CSP 점검 | 실제 CSP 아래에서 앱이 정상 동작하는지, 주입이 실행되지 않는지 |
| `worker/test` | 토큰 위조, `alg=none`, 한도 우회, 오류 내용 노출 |

## 배포 전 체크리스트

코드로는 할 수 없어 Firebase·Google 콘솔에서 해야 합니다.

- [ ] `firestore.rules` 게시 직후 앱 푸시 (순서는 [backend.md](backend.md#배포))
- [ ] **실제 Google 로그인과 Drive 녹취 고르기를 눌러 확인.** CSP 아래에서 이 둘은 시험하지 못했습니다
- [ ] Google Cloud 콘솔: 브라우저 API 키를 HTTP 리퍼러로 제한 (`chiseongan.github.io/*`, `localhost:5173/*`)
- [ ] Firebase App Check 켜기 (reCAPTCHA Enterprise): 앱이 아닌 호출을 막아 할당량 도용을 줄임
- [ ] Authentication → 승인된 도메인에서 쓰지 않는 도메인 빼기, Google 외 로그인 끄기
- [ ] Google Cloud 예산 알림 설정
- [ ] 프록시를 쓰면 KV 연결 (없으면 한도가 인스턴스마다 초기화됨), `ALLOWED_EMAIL_DOMAINS` 검토
- [ ] 저장소에 Dependabot 또는 정기 `npm audit`
- [ ] `js/legal-config.js`에 운영자 정보 입력, 법률 검토 후 `reviewed: true`

## 남은 위험

| 위험 | 이유 | 영향과 대응 |
|---|---|---|
| **같은 출처의 다른 페이지** | `chiseongan.github.io`의 다른 저장소 페이지는 이 앱과 저장소(localStorage·IndexedDB)를 공유 | 그 페이지의 스크립트가 토큰을 쓸 수 있음. 이 계정에 다른 Pages 사이트를 올리지 않거나, Firebase Hosting(`brainroom-777b0.web.app`) 또는 자체 도메인으로 옮기면 사라짐 |
| 팀장 권한 | 팀장은 다른 팀원 칸을 고치고, "가져온 기록"을 만들고, 연동 대상을 정함 | 가져온 기록은 표시가 남음. 팀원이 비공개 저장소 토큰을 쓴다면 팀장을 믿을 수 있어야 함. 그 저장소만 고른 읽기 전용 토큰을 권장 |
| 결정·퀘스트 | 협업 기능이라 팀원 누구나 고치고 지움 | 이력이 없음. 평가 근거로 쓰려면 이력 추가 필요 |
| 기록 시각 | 과거로는 속일 수 있음 (AI 대화 등 과거 작업을 담는 기능에 필요) | 미래만 막음 |
| 가짜 Meet 녹취 | 가져온 사람이 화자를 정함 | "내가 한 말"은 본인만 보이게 만들고 가져온 사람을 표시. 회의 기록 자체는 팀에 보임 |
| 명단의 이메일 | 교수자와 팀원이 방 문서로 읽을 수 있음 | 교수자 화면에는 안 나오지만 직접 읽으면 보임 |
| 할당량 소진 | Firestore 무료 한도는 프로젝트 전체 공유. App Check 전에는 로그인한 누구나 소진 가능 | 서비스 중단이지 유출은 아님 |
| 토큰 권한 | GitHub·Figma·Notion 토큰은 사용자가 만든 범위만큼 강함 | 안내에 읽기 전용만 권장 |
| 받아쓰기 | Web Speech는 음성을 브라우저 제조사 서버로 보냄 | 화면에 안내 |
| **보호자 확인의 강도** | 보호자가 진짜 보호자인지 앱이 증명할 수 없음. 아이가 다른 Google 계정으로 스스로 승인하거나 나이를 속일 수 있음 | 법이 정한 확인 방법에 맞는지 법률 검토 필요. 문자·이메일 확인을 더하면 강해짐 |
| 동의 철회 후 기존 방 | 철회·판 변경은 앱 화면과 새 참여를 막지만, 이미 들어간 방의 규칙 권한까지 즉시 끊지는 않음 (규칙 평가 한도 때문) | 앱을 거치지 않으면 접근 가능. 철회 시 계정 삭제를 함께 요청받아 처리 |
| 시험 범위 | 실제 운영 환경, 외부 침투 시험, 공급망 전체는 확인하지 못함 | 중요한 시연·평가 전에 별도 점검 권장 |
